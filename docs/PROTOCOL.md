# EVision V2 lighting protocol (USB VID 0x320F)

Documented from interoperability research on an **AJAZZ AK820 (wired, USB `320F:505B`, firmware V0103)**.
Confirmed by (1) talking to the real keyboard, (2) cross-checking the vendor app's packet builders, and
(3) USB captures of another keyboard with the same PID (Marvo KG980A, published in
[OpenRGB issue #3874](https://gitlab.com/CalcProgrammer1/OpenRGB/-/issues/3874)).
Each item is marked **[verified]** (seen on the AK820) or **[reported]** (other sources only).

## Transport [verified]
- Vendor HID collection: interface `MI_01`, usage page `0xFF1C`, usage `0x92`, report ID `4`, 64-byte input and
  output reports. On Windows a plain `WriteFile`/`hid_write` of 64 bytes works (sent as `SET_REPORT`).
- The keyboard **echoes every packet** on its input report. *Every* program holding the collection open
  receives every echo, so match on checksum + command + offset, not just the command byte. (The vendor app
  matches on the command byte only. That breaks when another RGB tool, e.g. OpenRGB, writes at the same time.)
- Echo latency is ~2 ms. Waiting for each echo gives ~80 full frames/s. Firing packets without waiting loses data.

## Packet [verified]
```
offset  0     1..2          3     4         5..6           7        8..63
        0x04  checksum LE   cmd   length    offset LE      status   data (<= 0x38 bytes)
checksum = (sum of bytes 3..63) & 0xFFFF   (unsigned)
status   = 0 in a good reply, 0xFF = unsupported command
```

## Commands
| cmd | meaning | notes |
|---|---|---|
| 0x01 | begin configuration | [verified] |
| 0x02 | end configuration: **applies** written config/colours | [verified]; also ends direct mode |
| 0x03 | read capabilities | [verified] reply `aa 55 00 00 0d 80 50 …`, byte 5 = LED slots (0x80 = 128) |
| 0x05 / 0x06 | read / write config | [verified] see below |
| 0x07 | read key map | [verified] 128 slots × 3 bytes `20 <modifier> <HID usage>`; `a0 01 00` = Fn |
| 0x0A / 0x0B | read / write custom colours | [verified] offset = 512 × area, 384 bytes = 128 × RGB |
| 0x12 | direct frame (live, not stored) | [verified] 384 bytes in 56-byte chunks |
| 0x13 | end direct mode | [verified] (the vendor app never sends it) |
| 0x1B | read LED table | [verified] identity except unused slots (0xFF) and one swap |
| 0x1A | (vendor app polls every 5 s) | [verified] AK820 replies status 0xFF |
| 0x04, 0x08, 0x09, 0x15, 0x17, 0x1C, 0xAA | **do not send** | capability/keymap/macro writes, firmware update paths |

## Config block (profile 0, read/write at offset 0) [verified]
```
[0] current profile  [1] mode  [2] brightness 0..4  [3] speed 0..4 (0 = fastest)
[4] direction (0 = left→right, 1 = right→left)  [5] random colour  [6..8] R,G,B  [18] custom colorset (ignored, see quirks)
```
The vendor app writes 0x1D bytes. Read-modify-write the block so unknown bytes survive.

Modes (names from the vendor app; the app's list values equal the device ids):
01 Corrugated · 02 Cloud · 03 Serpentine · 04 Spectrum · 05 Breath · 06 Normal (static) · 07 Reaction ·
08 Ripples · 09 Traverse · 0A Stars · 0B Flowers · 0C Roll · 0D Wave · 0E Cartoon · 0F Rain · 10 Scan ·
11 Surmount · 12 Speed · 14 Custom (per-key).

## LED index [verified]
`slot = column × 8 + row` of the firmware matrix (16 columns × 8 rows = 128 slots). The AK820 populates 82.
`evision_rgb/layout.py` has the full map, generated by joining the key map (0x07) with the key positions.

## Firmware quirks (AK820 V0103) [verified]
1. **Brightness 5 turns the LEDs off.** Valid range is 0..4. (The Marvo accepts 5.)
2. **Custom mode always displays memory area 0.** The colorset byte [18] is ignored, so areas 1..2 are storage only.
3. Config and colours apply on **END (0x02)**. Writing `config(mode = custom)` and `area-0 colours` inside **one**
   begin/end transaction switches cleanly. Two transactions briefly show the previous layout.
4. Direct mode times out back to the stored effect a short while after the last frame. A crashed host can't leave the
   keyboard stuck.
5. END (0x02) also leaves direct mode.

## Sequences
- **Set a hardware effect:** read config → modify → `01`, `06 (0x1D bytes @0)`, `02` → read back.
- **Per-key colours (stored):** `01`, `06 (mode = 0x14, [18] = 0)`, `0B × 7 (area 0)`, `02` → read back both.
- **Live animation:** `12 × 7` per frame (wait for each echo), keep-alive at least every ~150 ms, `13` to finish.
